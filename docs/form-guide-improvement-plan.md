# フォームガイド改善計画 v1.0(2026-07-14)

> 再評価(フォームガイド軸 3/5)を受けた段階的改善計画。
> 前提資産: 実写+注釈システム 87/345 種目(25.2%)、2 フレーム機構実装済み、
> 検査ツール `tools/check_form_annotations.py`、統合パイプライン(scratchpad/integrate_batch.py 方式)。

## ゴール設定

| 指標 | 現在 | Phase B 後 | Phase C 後 |
|---|---|---|---|
| 写真カバレッジ(全 345 種目) | 25.2% | 50% | 65%+ |
| 露出加重カバレッジ(利用頻度上位 100 種目) | 約 60% | 90% | 100% |
| 2 フレーム(動き表現)種目 | 1 | 12+ | 40+ |
| 競合スコア(フォームガイド軸) | 3/5 | 3.5/5 | 4/5 |

戦い方: Hevy/Fitbod の「動画で全種目」を追わず、**「教科書式注釈 × 日本語キュー」の質的優位を保ったままカバレッジと動き表現を積み増す**。動画 mp4 同梱は §-1 Lock により引き続き禁止。

---

## Phase A: 磨き込み(リリース前・工数 約 1 日)

既存 87 種目の体験を仕上げ、ASO 資産化する。

1. **デザイン統一**: `AnnotatedFormView` の写真カードに `premiumDiagramCard()`(または hero 用派生)を適用し、直下の筋肉図カードと格を揃える
2. **VoiceOver 修正**: `AnnotationDot` / `AnnotationLeaderLine` に `.accessibilityHidden(true)`(カードのみ読み上げ)
3. **Dynamic Type 対策**: 注釈カードに `.dynamicTypeSize(...(.large))` 上限(高密度オーバーレイの標準手法)。本文側のステップ解説は無制限のまま
4. **未カバー 258 種目への合図**: 詳細画面に控えめな「フォーム写真は順次追加中」フッター(1 キー追加)— 機能の存在をライブラリ全体に伝える
5. **ASO 反映**: スクリーンショット 1 枚目のフォーム注釈画面を最新 87 種目版に更新

完了条件: 検査ツール 0 違反維持 + CI グリーン + デザイン再スコア 4.4 復帰。

## Phase B: カバレッジ 50% 到達(v1.0.x・工数 1〜2 週)

Pexels パイプライン(確立済み)の継続で findable な残種目を回収する。

- **対象選定**: 残り 258 のうち、①ワークアウトテンプレート出現頻度上位、②初心者導線(ウォームアップ/ストレッチ)を優先。バリエーション系(グリップ違い等)は親種目の写真+注釈文言差し替えで転用可否を判断
- **見込み**: これまでの採用率(87 採用 / 約 99 試行 = 88%)から、+80〜90 種目が現実的 → 計 170 前後(約 50%)
- **2 フレーム拡張**: 「スタート/ボトム」のペア写真が取れる種目(スクワット系・プレス系・ヒンジ系)を 12 種目以上。判定基準は既存(明確な別フェーズのみ、無理はしない)
- **品質ゲートは現行 5 段を維持**(フォーム審査 → ピクセル照合 → 静的検査 → レンダリング実測 → CI)。検品オーバーレイ必須、最終照合は人(私)が実施

## Phase C: 動き表現と unfindable の解消(v1.1・工数 2〜3 週+検証)

調査レポート(3D ポーズ→AI 仕上げ)を実行に移す。

- **対象**: ① Pexels に存在しないことが確定した 12 種目(ブルガリアンスプリットスクワット、バーベルヒップスラスト、デッドバグ、V アップ、ダイヤモンドプッシュアップ、ライイングレッグカール、リストフレクサーストレッチ、ハッピーベイビー、4 の字ストレッチ、スーパーマン、ダンベルシュラッグ、ステアクライマー)② 動きが本質の主要種目(デッドリフト引き上げ、バーピー遷移、クリーン系)の 2〜3 フレーム連作
- **パイプライン**: PoseMy.Art / Blender でポーズ作成(正確性を構造的に担保)→ SDXL または Flux-schnell(商用安全ライセンス)+ Depth ControlNet で写実イラスト化 → 手・器具接点のみ人力検品 → 既存 JSON スキーマにそのまま搭載
- **キャラクター一貫性**: 単一キャラクターリファレンスで統一(illustration トーンは実写と区別がつくよう意図的に「図解」らしく)
- **コスト**: 計算費数ドル、律速はポーズ作成(バーベル系 0.5〜1 日/種目、リグ資産が貯まると加速)
- **判断ゲート**: 最初の 3 種目でスタイル・品質を確認してから量産(NG なら有償ストック購入にフォールバック、2 枚 ≈ ¥3,000〜6,000/種目)

## Phase D: 体験の深化(v1.2+)

- **フレーム自動再生**: 2〜4 フレームをゆっくりループ表示(画像ベースのため §-1 に非抵触、Reduce Motion 尊重)
- **キュー連動 AI コーチ**: AI 要約が「今日のスクワットは深さを意識」のようにキュー ID を参照 → 詳細画面の該当キューをハイライト
- **自重系 Lottie**(任意): 既製パック(約 $30・65 種目)を lottie-ios 基盤(復活済み)で再生し、自重種目の動き表現を底上げ

## リスクと対策

| リスク | 対策 |
|---|---|
| Pexels の在庫枯渇(Phase B 後半) | 採用率が 50% を切った時点で Phase C 前倒し |
| AI 生成の手・器具の破綻 | ポーズは 3D 側で固定、生成は仕上げのみ。接点部の人力検品を必須化 |
| Dynamic Type / iPad 分割画面での重なり | Phase A の上限キャップ+iPad 対応判断時に検査幅 288pt を追加 |
| 文言と写真のフェーズ不一致 | 検品プロセスに「キュー文言がその写真のフェーズに適合するか」を明示項目化 |

## 直近アクション(承認後すぐ)

1. Phase A の 4 コード修正を 1 コミットで適用 → 検査 → CI
2. Phase B ウェーブ 5(20 種目)をワーカー投入
