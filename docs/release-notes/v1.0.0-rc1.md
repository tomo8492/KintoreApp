## Highlights

- **Auto-Renewable Subscription pivot complete.** Single-tap purchase of the
  `premium` entitlement via either `workoutkit_monthly_980` (¥980 / month)
  or `workoutkit_yearly_4900` (¥4 900 / year), both with a 7-day free
  trial. All StoreKit traffic flows through the RevenueCat 5.x SDK via the
  in-app `PurchaseManager` wrapper (the legacy `StoreKitClient` path was
  retired in `7923a7a`).
- **Apple 3.1.2 disclosure on hard paywall.** Footer now spells out
  subscription auto-renewal terms, cancellation path, free-trial conversion,
  and links to Privacy / Terms in the user's locale (commit `b876bea`).
  This satisfies App Review Guideline 3.1.2 in a single, scrollable surface
  rather than burying it behind a separate "Legal" sheet.
- **AI Coach (iOS 26+) ships as default-off graceful fallback.** Three-line
  session summary (recap / standout exercise / tomorrow's note) produced
  on-device via Foundation Models Framework. On iOS 18–25 the entire
  `AICoachView` is hidden, no UI cost.
- **Rest Timer Live Activity is a separate `ActivityConfiguration`** in the
  same Widget Bundle as the session Live Activity. Started from
  `SessionStore.completeCurrentSet`, finished by `finish()` / `abort()`.
  Lock-screen and Dynamic Island both use `Text(timerInterval:countsDown:)`
  for local rendering — zero push updates.
- **watchOS Smart Stack widget.** `accessoryRectangular` showing today's
  status (completed ✅ / not started 📅 + total sets). Data is shared
  through App Group `UserDefaults` (`group.com.tomo.workoutkit`) as
  serialized `TodaySessionSummary` JSON via `WatchSummaryBridge` — SwiftData
  is deliberately not exposed to the Widget Extension to keep activation
  cost flat.
- **Mac-side build path is green.** `xcodebuild test
  -only-testing:WorkoutKitTests CODE_SIGNING_ALLOWED=NO` reports
  **155 / 155** under Xcode 26.5 / iPhone 17 simulator
  (commit `4e25013` made this true; CI workflow `f7f2b53` enforces it).
- **App Store submission kit is feature-complete.** All 12 metadata
  source files (6 fields × ja/en) audited under-cap by
  `docs/app-store/CHAR_COUNT_AUDIT.md`. Privacy declarations cross-checked
  by `docs/app-store/privacy-nutrition-label.md`. App Review notes
  (English) at `docs/app-store/app-review-notes.md`. 50 screenshots
  captured (`82d0950`, `d84c639`, `360d1bc`, `8a3a010`, `576a857`),
  Apple Watch frame remains pending hardware capture.

## Breaking changes vs. earlier internal drafts

These are noted for archeological clarity — there are no actual users yet,
so nothing "breaks" externally.

- **IAP model rewritten.** The earlier internal spec (CLAUDE.md v0.4
  / the `[1.0.0]` draft in `CHANGELOG.md`) described a single
  Non-Consumable IAP `com.tomo.workoutkit.pro.unlock`. v1.0 replaces this
  with the subscription model above. The old product ID is **not** wired
  up anywhere in source; if you had a sandbox tester linked to it during
  early development, remove that product from "Ready to Submit" in
  App Store Connect before final submission (covered in
  `docs/DISPATCH_v1.0.md` §4 step 8).
- **Min iOS raised from 17.0 → 18.0.** Live Activities reliability fixes
  and watchOS Smart Stack widget APIs are the drivers. Existing CLAUDE.md
  text in §-1 was updated; xcconfig (`Config/Shared.xcconfig`) sets
  `IPHONEOS_DEPLOYMENT_TARGET = 18.0` accordingly.
- **`StoreKitClient` is gone.** All call sites now go through
  `PurchaseManager` and the `PurchaseRestoring` protocol. Anything in
  `Tests/` that imported `StoreKitClient` was updated in the same commit
  (`7923a7a`).

## Known issues / pending before final v1.0.0

These do **not** block ASC submission of `v1.0.0-rc1` for TestFlight, but
should be cleared before a public v1.0.0 tag.

### Pending external actions

- **M2 — GitHub Actions first-pass confirmation.** `gh` CLI is currently
  unauthenticated in the worktree, so the Actions UI must be checked
  manually after each push. Not a blocker, just an ergonomics gap.
- **M6 — Apple Watch screenshot.** All 49 iPhone + iPad screenshots are
  in the repo. The single Apple Watch frame still needs to be captured on
  hardware (the watchOS simulator Smart Stack preview path described in
  `docs/app-store/screenshot-captions.md` works but produces a low-fidelity
  PNG that is not what we want for the App Store hero).
- **M8 — ASC metadata paste.** tomo's manual UI step. Files at
  `docs/app-store/{ja,en}/*.txt`, all under-cap per
  `docs/app-store/CHAR_COUNT_AUDIT.md`.
- **M9 / M10 — Blocked on Apple Developer enrollment.** Enrollment
  paperwork is the long-pole here.

### Pending source / docs cleanups (post-`-rc1`)

- **`NSPrivacyCollectedDataTypes` parity.** `PrivacyInfo.xcprivacy`
  declares an empty `NSPrivacyCollectedDataTypes` array even though the
  ASC declaration will include Purchases → Purchase History and
  Identifiers → User ID (RevenueCat-driven). Mirroring the ASC entries in
  the manifest is "Flag #1" in `docs/app-store/privacy-nutrition-label.md`
  and remains open. Low priority — ASC declaration is authoritative.
- **Legal HTML/MD drift.** `docs/legal/privacy-policy.html` and
  `.en.html` were generated from an older revision of the `.md` sources
  and then hand-edited. After this RC the third-party-services line was
  patched to drop "Local Notifications" and mention RevenueCat, but the
  HTML files still describe the IAP as "Pro" rather than "Premium
  subscription" in their §2.3 table. Plan a single pandoc-or-manual
  regeneration pass before final v1.0.0; see
  `docs/app-store/privacy-nutrition-label.md` §7.6.
- **Stale `%lld` siblings in Localizable.xcstrings.** Seven dynamic-format
  keys got hand-translated `%@` variants in this RC's docs-audit pass
  (commit added by `task/docs-audit-v1`); the original `%lld` siblings
  are now marked `extractionState: stale` and could be removed in a
  future cleanup. Harmless until then.
- **`tools/sd-batch/`.** The local Stable Diffusion image-generation
  pipeline directory still exists from early planning but is not used by
  v1.0 (the app ships anatomical SVG diagrams + step text instead). Safe
  to delete in a follow-up, retained for now in case the v1.1 photo
  pipeline reuses parts.
